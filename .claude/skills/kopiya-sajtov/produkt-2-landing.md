# Продукт 2. Лендинг из копии сайта

Приложение к скиллу kopiya-sajtov. Вход: html-архив (продукт 1) или живой
сайт. Выход: лёгкий лендинг, пригодный для размещения и рекламы. Формы —
по скиллу formy-na-statike.

## 1. Принципы лендинга (выбор на этапе планирования)

1. **По главной странице со всплывающими заглушками** — модальные окна
   с кратким содержимым страниц исходника.
2. **Лендинг-прокладка** — свои услуги и контакты на главной, наружу ведут
   ссылки на основной сайт (кейс: 133 внешних ссылки — штатная схема
   для рекламных кампаний).
3. **На основе содержания всего сайта** — переработанная структура.

Принципы сочетаются в смешанном варианте: часть страниц — собственное
содержимое (политика, контакты, услуги, «о компании»), отдельные разделы
(например, каталог) — ссылками на основной сайт. Для смешанного варианта
составить и утвердить список разделов по каждому режиму; по нему же
проверяется приёмка.

## 2. Сборка

- **Перезапускаемая сборка** — основное правило: любая ручная правка
  результата теряется при повторном прогоне. Все правки (иконки, honeypot,
  webp, цели) вносятся в скрипт сборки, а не в собранные файлы.
- Сборка скриптом из архива: чистка корзинного стека, переписывание
  ссылок, цели, копирование ресурсов, чистка CSS.
- **Соответствие адресов** — из mapping выгрузки, а не генерируется
  обрезкой расширения (файл katalog.html ↔ адрес /katalog).
- Ссылки на живой сайт без расширения, вложенные страницы — только
  относительные пути от файла (ловушка «от корня» из SKILL.md).

## 3. Чистка CSS

- **Битые исходные CSS**: несовпадение скобок, дублирующиеся копии секций
  — наивный разбор падает. Нужен устойчивый разбор с дедупликацией
  по сериализованному тексту и рекурсией внутрь @media.
- **Опасность чистки по маркерам**: фильтр по слову выбросил живые стили
  (кейс: чистка по «yith» потеряла поисковую форму в шапке; дефект нашёлся
  только в визуальной сверке). Правило: маркерная чистка обязана иметь
  белый список исключений (классы из js — из инвентаризации) и визуальную
  проверку после каждой чистки.
- Дедупликация по нормализованному тексту; аудит результата — с поправкой
  на артефакты нормализации (CSSOM переписывает odd → 2n+1, :after →
  ::after, кавычки у атрибутов; шаги keyframes показываются как селекторы).
  Сравнение «текст против CSSOM» без нормализации даёт ложные «потерянные
  селекторы».
- Инвентаризация шрифтов и иконок до чистки; оставлять только задействованное.

## 4. Картинки и вес

- Конвертация в webp; контроль веса по инвентаризации (размеры по точкам
  сброса — из SKILL.md, этап П).
- Битые jpeg внутри `<picture>`: браузер берёт source — проверять пары
  jpeg/webp вместе (см. SKILL.md, ловушки).

## 5. Цели Метрики

- Существующую разметку целей собрать до любых правок (карта «как
  считалось раньше»); на её основе — новая разметка и проверка
  переносимости целей.
- Перечень целей для кабинета Метрики — отдельным файлом с неймингом
  ценность_тип_действие_конкретика_название; легаси-дубли целей не
  заводить.

## 6. Формы

По скиллу formy-na-statike: инвентаризация хостинга и почты до
планирования, выбор схемы (mail()/SMTP), CRLF-конверт, журнал-страховка,
приёмка mail-tester до боевого запуска.

## 7. Приёмка

1. Перечень утверждённых разделов (для смешанного варианта) сверён
   с результатом: где «прокладка», где собственное содержимое.
2. Проверка всех локальных ссылок; внешние ссылки ведут на основной сайт
   по утверждённому списку.
3. Визуальная сверка после каждой чистки CSS (скриншоты до/после).
4. Веса и состав файлов сверены с целью сборки.
5. Формы — приёмка по скиллу formy-na-statike.
6. Локальная проверка при base-теге — только с перехватом запросов к домену
   (см. SKILL.md, общая приёмка).
7. Слайдеры — проверять пролистыванием, не первым кадром.
