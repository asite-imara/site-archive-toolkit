# План: чистая облегчённая копия moskva.prom-opora.ru

Дата составления: 2026-09-17. Статус: план утверждён и исполнен полностью
(2026-09-17 — 2026-09-18), сайт выложен и работает (базовый деплой + слеш-схема).
Поведенческая приёмка владельца — 2026-09-19, замечания на доработке.
Детальная хронология — в отчётах этапов и памяти plan-moskva-kopiya.

## Цель

Собрать из архивной копии site-backup-html полную статическую копию сайта для
выкладки на moskva.prom-opora.ru (/home/p/promopora/moskva/public_html, FTP
promopora_claudem): без следов движка, чистая разметка, облегчённые стили,
работающие фильтр, поиск, корзина, обновляемые цены.

## Принятые решения

1. Корзина: localStorage + оформление одним письмом через SMTP (схема отработана
   на kirov.prom-opora.ru). Кнопка «В корзину» на карточках (вместо «Предзаказ»
   с формой ms3), количество из существующего поля карточки; korzina.html
   перерабатывается: перечень позиций, правка количества, удаление, итог по ценам
   из prices.json; форма контактов и отправка — письмо со списком позиций на
   [почта цели moskva] через SMTP, журнал заявок CSV, скрытая копия,
   mail-errors.log закрыт в .htaccess. Деградация без JS/localStorage — ведёт на
   контакты. Мультипозиционный заказ — основание выбора этого варианта.
2. Поиск: клиентский по JSON-индексу (названия и описания товаров). Серверный
   поиск YITH (search.html) не воспроизводится.
3. Цены: prices.json (ключ — id товара) + prices.js подставляет цены по id
   в карточки и корзину; дефолтные значения остаются в HTML как запас при
   недоступности JSON. Обновление цены — правка одного файла по FTP.
4. Признаки движка удаляются полностью, включая типовые классы (wp-, woocommerce-
   и прочие) — по требованию владельца.
5. Выкладка — только после подтверждения владельца.

## Исходные факты (обследование site-backup-html от 2026-09-17)

- Движок исходного сайта: MODX + miniShop3 + FormIt (не WordPress).
  Скрипты: assets/components/minishop3/* (17 файлов), formit.js,
  inc/js/catalog-filter.js (серверный, cf_ajax=1, ждёт JSON от сервера).
- Следы WooCommerce (наследие прежнего шаблона): классы woocommerce-* в карточках
  товаров, формы ms3_form на 458 страницах, поиск yith-ajaxsearchform,
  инлайновые стили с woocommerce-селекторами.
- Пути wp-content/uploads — на 124 страницах (старые картинки, частично совпадает
  с битыми jpeg из инвентаризации).
- CSS: inc/css/custom.css — 1,5 МБ (загружается на всех страницах),
  theme-child.css — 496 КБ, fa.all.min.css, slider.css, инлайновые <style>-блоки.
- Цены в разметке карточек: <span class="woocommerce-Price-amount amount">
  (текст цены + знак валюты); id товара есть в скрытом поле формы (input name=id).
- Всего html-страниц в архиве: 459.

## Этапы

### Этап 0. Подготовка и инвентаризация
Рабочая папка сборки (архив site-backup-html не трогаем). Индекс 459 страниц:
карта шаблонов (главная, раздел каталога, карточка товара, инфо-страницы,
корзина, поиск), перечень скриптов, стилей, классов, картинок. Карта типов
страниц — основа для разделения CSS (этап 5).

### Этап 1. Чистая разметка
Перенос исправлений из инструкции разработчику
(docs/reports/instrukciya-razrabotchiku-nedostatki-prom-opora-2026-09-17.md):
блок Б — 85 адресов jpeg→webp; блок Г — 10 утраченных картинок (9 из архива,
1 — parkovye-opory — заменить или получить от клиента); блок Д — 14 мест
разорванной разметки (10 portfolio + 4 «Изготовление»); проверка отсутствия
base на стейджинг. Эталон — страницы-представители каждого шаблона.

ЗАВИСИМОСТЬ: снята 2026-09-17 — блок Г решён заглушками. 10 утраченных картинок
не восстанавливаются; вместо них 10 заглушек из archive-2026-09-17_22-59-13/archive/
(img-01…img-10-800px.webp), размещаются в сборке по /upload/zaglushki/.
Конфигурация: sborka-moskva-prom-opora-2026-09-17/zaglushki-mapping.json;
отчёт: docs/reports/report-zaglushki-blok-g-2026-09-17.md. Затронуты 2 страницы:
o-kompanii.html (4 адреса, noscript) и izgotovlenie-…html (6 слайдов галереи).

### Этап 2. Устранение признаков движка
- Классы woocommerce-* → нейтральные (shop-*), ms3_*/data-ms3-* → свои имена;
  скрипт-переименование по словарю, согласованному с CSS и JS.
- Пути wp-content/uploads → /upload/ (совместно с этапом 1).
- Каталоги assets/components/* (minishop3, formit) в сборку не попадают;
  хэши-суффиксы движка (__8506e9 и т. п.) исчезают вместе с ними.
- Чистка мета-тегов и разметки с упоминанием движка (генераторы, YITH).
- Приёмка: grep по финальной сборке (wp-, woocommerce, modx, minishop, formit,
  yith, ms3) — 0 вхождений.

### Этап 3. Скрипты: чистка и замена
- Убираются: 17 файлов miniShop3/FormIt, серверный catalog-filter.js.
- Оставляются: uikit.min.js, uikit-icons.min.js, custom.js, theme.js,
  iziToast (если задействован в новых формах).
- Новые локальные скрипты:
  - filter.js — клиентский фильтр раздела: чекбоксы, радиокнопки, диапазон
    цены, сортировка, «показать ещё»; данные из JSON-индекса товаров раздела,
    генерируемого при сборке из карточек;
  - cart.js — корзина в localStorage (id, название, цена, количество),
    добавление с карточек, страница корзины, оформление;
  - search.js — клиентский поиск по JSON-индексу;
  - prices.js — подстановка цен по id из prices.json.
- PHP-обработчик заказа (по схеме kirov): SMTP smtp.timeweb.ru:587 от
  [почта цели moskva], журнал заявок CSV (CP1251, ;), скрытая копия,
  mail-errors.log; файлы закрыты в .htaccess. Тело письма — CRLF
  (с голым \n smtp.timeweb.ru рвёт соединение).

### Этап 4. Цены (обновляемость)
prices.json генерируется при сборке из разметки карточек (ключ — id товара).
prices.js подставляет значения в карточки и корзину. Обновление цены — правка
одного файла по FTP. Опционально: мини-редактор цен на сервере с паролем.

### Этап 5. CSS: трёхслойная структура (отдельный отчёт)
- Инвентаризация: классы каждой страницы × правила CSS — карта использования.
- critical.css первого экрана — по типам шаблонов (5–7 типов), инлайн в <head>
  каждой страницы: максимальная скорость отрисовки.
- common.css — общие стили сайта (сетка, шапка, подвал, кнопки, базис UIkit).
- page-*.css — стили конкретных типов страниц, подключаются только на них.
- Вычистка неиспользуемых правил; контроль размеров до/после; визуальная сверка
  скриншотами ключевых страниц до/после.
- Отдельный отчёт report-css-razdelenie-...md: размеры слоёв, что удалено,
  что осталось в инлайне, список рисков.

### Этап 6. Счётчик Метрики
Вшивается счётчик (id по аналогии с kirov — отдельный от [номер счётчика] либо единый,
решение владельца) и цели JavaScript-события: добавление в корзину, открытие
корзины, отправка заказа, клик по телефону/почте/мессенджерам, переходы в
разделы. Перечень целей готовит владелец проекта до этапа 6; в сборке
предусмотреть вызовы целей в cart.js/filter.js и на формах.

ЗАВИСИМОСТЬ: владелец делает счётчик и список целей до/во время этапа 6.

### Этап 7. Сборка, проверка, выкладка
Локальный сервер; прогон проверки ссылок и ресурсов по всем страницам (скрипты
инвентаризации); скриншоты ключевых страниц; FTP-выкладка на
/home/p/promopora/moskva/public_html — только после подтверждения владельца.
Итоговый отчёт.
