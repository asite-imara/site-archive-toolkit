## Сложности, выявленные в сессии лендинга (для проработки скиллов)

1. **Битые исходные CSS**. custom.css: 18 154 открывающих скобки против 17 066 закрывающих, 5–7 дублирующихся копий секций. Наивный разбор падает; нужно устойчивое дерево-парсирование (tinycss2) с дедупликацией по сериализованному тексту и рекурсией внутрь @media.
2. **Опасность чистки стилей по маркерам**. Фильтр по слову «yith» выбросил стили поисковой формы в шапке — дефект нашёлся только в визуальной сверке. Правило: маркерная чистка обязана иметь белый список исключений и проверку визуала после каждой чистки.
3. **Шрифты иконок с CDN**. Часть семейств шрифтов (FontAwesome для класса .fa) подключалась только через CDN; после чистки внешних адресов иконки исчезли, а класс .fa-solid вообще не был описан ни в одном стиле исходника. Нужен этап инвентаризации: список всех семейств шрифтов в CSS и их источников до удаления чего-либо.
4. **Перезапускаемая сборка**. Любая ручная правка результата теряется при повторном прогоне скрипта. Все правки (иконки, honeypot, webp) вносятся в скрипт сборки, а не в собранные файлы. Это уже отработано и должно стать правилом скилла.
5. **Ссылки на живой сайт без расширения**. Файл katalog.html соответствует адресу prom-opora.ru/katalog — соответствие берётся из mapping.txt, а не генерируется обрезкой .html.
6. **Дефекты живого сайта в копии**. Битые jpeg, двойное экранирование кавычек в style, слайдер, у которого фон работает только скриптом. Политика: воспроизводить как в источнике, отдельно фиксировать как улучшение (например, исправление style-атрибутов).
7. **Пакетная зависимость**. tinycss2 и Pillow пришлось устанавливать; согласование установки — обязательный шаг плана (граница из инструкции).

## Задача на проработку: инвентаризация адресов сайта (добавлено 2026-09-16; исполнено 2026-09-16 — отчёт docs/reports/report-inventarizaciya-adresov-prom-opora-2026-09-16.md, файлы в inventarizaciya-prom-opora-2026-09-16/)

Предпосылка: при создании архива рекурсивный обход нашёл ~25 тысяч ссылок при
заметно меньшем числе содержательных страниц (мусор: параметры, пагинация,
дубли). Решение сессии 2026-09-16: двухэтапный порядок «сначала список, потом
скачивание». Справка: docs/reference/spravka-wget-zerkalirovanie-saytov-2026-09-16.md.

Проработать и внести в скилл «Полная статическая копия сайта» этап
«инвентаризация адресов»:
1. Сбор адресов: sitemap.xml (все карты: основной домен, new-стейджинг, kirov) + обход в режиме --spider с фильтрацией параметров.
2. Чистка списка: дубли, адреса с параметрами, чужие домены, неактуальные.
3. Сверка по кодам ответа сервера: отбрасывать 404 и цепочки редиректов.
4. Сверка списка с sitemap: полнота охвата до скачивания, а не по факту.
5. Выгрузка архива по списку: `wget -i spisok-adresov.txt` + ключи из справки.
6. Побочный продукт списка: проверка битых jpeg, SEO-аудит адресов.
