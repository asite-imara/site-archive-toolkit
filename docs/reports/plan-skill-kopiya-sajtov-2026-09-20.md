# План скилла «копирование сайтов»

Дата: 2026-09-20
Статус: утверждён владельцем в сессии (формат «SKILL.md + приложения», глубина продукта 3 — «методика по этапам»).

## 1. Основание

Архитектура скилла-«зонта» утверждена владельцем 2026-09-20
(docs/reports/plan-skill-formy-na-statike-2026-09-20.md, п. 1.13): общая
цепочка (инвентаризация → архив → аудит/ТЗ) и три продукта:

1. Полный html-архив сайта (архив + аудит + ТЗ).
2. Лендинг на основе html-архива (три принципа + смешанный вариант).
3. Полноценный сайт на html, css, js — «чистая максимально облегчённая
   копия» с сохранением дизайна, устранёнными недостатками и планом
   продвижения.

Смешанные варианты: часть разделов — «прокладка» (ссылки на основной
сайт), часть — собственное содержимое; список разделов утверждается
на этапе планирования и служит основой приёмки.

Существующие методики к этой схеме: архив site-backup-html (продукт 1),
лендинг kirov (продукт 2, «прокладка», 133 внешних ссылки), сборка
moskva (продукт 3, этапы 0–7). Скилл formy-na-statike — вспомогательный
компонент для продуктов 2 и 3.

## 3. Структура скилла

Расположение: `.claude/skills/kopiya-sajtov/`.

### SKILL.md (шапка, цепочка, инвентаризация, выгрузка, аудит)

- Назначение; архитектура цепочки и трёх продуктов; смешанные варианты;
  правила уточнения конечной цели и предлагания веток.
- Начало задачи: терминология сайтов; вопрос конечной цели одним
  предложением («дойдём до X, дальше могу сделать Y или Z — нужно ли?»).
- Этап «Планирование и инвентаризация»: чек-лист п. 1.12 (ключи, внешние
  ссылки, классы/id, разметка целей, типы страниц, иконки, картинки,
  движковые каталоги) + происхождение (движок, домены, хостинг, почта) +
  URL-схема (слеш против .html — фиксируется до сборки); вопросы
  владельцу одним списком; закрытый вопрос = ответ или «не применимо»
  с причиной.
- Этап «Архивная выгрузка» (общая основа всех продуктов): проверка
  окружения (wget/httrack/curl/Python — установки отдельным
  согласованием), BFS-обход волнами, canonical-ключи, классификация по
  Content-Type, temp с хэш-именами, лимиты и бэкофф; ловушки: base-тег
  и поддомены, относительность путей, query-ключи, битая разметка,
  цепочки HTML → CSS → url(), коллизии путей.
- Этап «Аудит и ТЗ» (завершение цепочки).
- Продукты: 1 — кратко с критериями приёмки; 2 и 3 — резюме и отсылка
  к приложениям.
- Общая приёмка: локальная проверка при base — только с перехватом
  запросов к домену (п. 1.3); слайдер — проверять пролистыванием (п. 1.4).
- Использование субагентом; кейсы-примеры (не инструкции); источники.

### Приложение produkt-2-landing.md

Принципы лендинга и смешанный вариант; перезапускаемая сборка (правки
в скрипт сборки, не в результат); чистка CSS (белый список классов из
js, дедупликация, визуальная сверка после каждой чистки); инвентаризация
шрифтов и иконок (FontAwesome/fa-solid кейс); webp и вес; цели Метрики
(существующая разметка целей до правок); формы — вызов скилла
formy-na-statike; приёмка лендинга.

### Приложение produkt-3-polnaya-kopiya.md

Методика по этапам 0–7 (обобщение опыта moskva, без привязки к скриптам
проекта): карта страниц и инвентаризация; сборка и правка дефектов
разметки; удаление следов движка (классы, скрипты, теги, абсолютные
ссылки); каталог на клиенте (JSON-данные, корзина, поиск, фильтр) и
обработчики форм по скиллу formy-na-statike; CSS-разделение (чистка,
дедупликация, критические стили, аудит артефактов CSSOM); Метрика и цели;
robots/sitemap; URL-схема и 301; деплой (.htaccess первым, только с
подтверждения владельца); поведенческая приёмка в браузере. Плюс план
продвижения как завершающий блок продукта 3 (п. 1.13).
