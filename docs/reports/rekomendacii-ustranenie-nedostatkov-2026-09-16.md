# Рекомендации: устранение недостатков по итогам инвентаризации prom-opora.ru

Дата: 2026-09-16. Источник данных: docs/reports/report-inventarizaciya-adresov-prom-opora-2026-09-16.md и
inventarizaciya-prom-opora-2026-09-16/inventar-adresov...csv, bitye-ssylki...csv.
Файл содержит только рекомендации — правок страниц, карт и файлов не выполнялось.

## Блок 1. Правки сайта (исполнитель: разработчик / хостинг)

### 1.1. Тег base на стейджинг-домен — приоритет: критично

- Где: карточки товара /katalog/rmp-14/ и /katalog/zf-20-4-k300-1-5/.
- Суть: в разметке стоит base href="https://new.prom-opora.ru/" — все относительные
  ссылки, картинки и формы этих страниц работают на стейджинге. С этих двух страниц
  уходит 198 ссылок на new.prom-opora.ru (102 и 96).
- Действие: удалить или исправить base href в источнике карточек (вероятно, в самом
  тексте ресурса или в шаблоне карточки). После правки перегенерировать кэш страниц.
- Почему критично: посетители этих карточек частично взаимодействуют со стейджингом
  (корзина, формы), поисковая машина может учитывать ссылки на поддомен.

### 1.2. Массовая замена jpeg-адресов на webp — приоритет: критично

- Суть: 95 битых картинок (404) с расширением .jpeg/.jpg. Проверка показала: у 85 из
  них на сервере есть работающий .webp-двойник с тем же именем — сайт переведён на
  webp, а разметка частично осталась со старыми адресами.
- Действие: массовая замена расширений в разметке (ресурсы CMS) с .jpeg/.jpg на .webp
  по перечню из bitye-ssylki...csv (колонка «Адрес», фильтр «картинка», код 404).
  Альтернатива на сервере — rewrite-правило jpeg → webp, но это лечит симптом, а не
  разметку; правка в источниках предпочтительнее.
- Затронутые страницы (по числу битых картинок): /izgotovlenie-metallokonstrukczij-na-zakaz/
  (72), /portfolio/ (11), /o-kompanii/ (9), /oporyi-zh-d-kontaktnoj-seti/ (6),
  /dostavka-oplata/ (2).

### 1.3. Картинки без webp-двойника — приоритет: желательно

Суть: 10 адресов, где нет ни jpeg, ни webp (файлы утрачены). Перечень:

| Адрес файла | Страница |
|---|---|
| /upload/catalog/prom-opora-catalog-parkovye-opory.jpeg | /o-kompanii/ |
| /upload/catalog/prom-opora-catalog-svetofor-gran-01..06.jpeg (6 шт.) | /izgotovlenie-metallokonstrukczij-na-zakaz/ |
| /wp-content/uploads/catalog-prom-opora-rmg-1.jpg | /o-kompanii/ |
| /wp-content/uploads/prom-opora-catalog-omgdz-1.jpg | /o-kompanii/ |
| /wp-content/uploads/prom-opora-catalog-svetofor-gran.jpg | /o-kompanii/ |

Действие: загрузить файлы заново (есть в архивной копии site-backup-html — сверить
целостность) либо заменить в разметке на актуальные изображения из тех же разделов.

### 1.4. Разорванная разметка — приоритет: желательно

- Где: /portfolio/ — 10 атрибутов src вида «...jpg width="» (незакрытый атрибут);
  /izgotovlenie-metallokonstrukczij-na-zakaz/ — 3 адреса вида
  «https://prom-opora.ru/ p-content/uploads/...» (разрыв внутри адреса; сами файлы
  по корректным адресам wp-content/uploads/... отсутствуют — см. 1.3).
- Действие: восстановить синтаксис атрибутов в разметке портфолио; для трёх адресов —
  после решения по 1.3 проставить рабочие адреса.

### 1.5. Служебная страница /404/ и прочее

- На заметку: страница /404/ включена в sitemap.xml (462-я). Обычно её из карты
  исключают; решение за владельцем сайта.

## Блок 2. SEO (исполнитель: SEO-специалист)

### 2.1. 404-адрес в sitemap.xml — приоритет: критично

- Где: /katalog/kronshtejn-1k1-0-5-0-5-f2-czink-xolodnyij/ — в карте сайта, на сервере
  отдаёт 404; единственная страница из карты с не-200.
- Действие: убрать адрес из sitemap.xml (карта пересобирается автоматически — проверить
  источник генерации, чтобы адрес вернулся при следующем обновлении). Если карточка
  нужна — восстановить ресурс в CMS и вернуть в карту. 301-редирект не обязателен:
  страница была товаром, аналоги соседних моделей (1К1-...) остались живы.

### 2.2. Keywords пусты на всех 462 страницах — приоритет: на решение владельца

- Суть: мета keywords не заполнена нигде (снимок в inventar-adresov...csv, колонка
  Keywords). Поисковые машины ключевые слова почти не учитывают, массовость заполнения
  смысла не имеет.
- Рекомендация: не заполнять массово. Опционально — только для 4 посадочных страниц
  (opory-*) и 5 разделов каталога, если будет вестись работа с Яндекс.Директ или
  внутренним поиском. Иначе — осознанно оставить пустыми и закрыть вопрос.

### 2.3. Позитив, подтверждающий отсутствие работ

- canonical на всех 462 страницах указывает сам на себя — дублей по каноническому
  адресу нет, работ не требуется.
- Редиректов нет, контентных страниц вне sitemap нет, пагинация закрыта в robots.txt
  и Clean-param настроен — охват и чистота адресов в норме.

## Порядок внедрения

1. 1.1 base href (2 карточки) — быстро, закрывает 198 ссылок на стейджинг.
2. 1.2 массовая замена jpeg → webp (85 адресов) — одно действие закрывает большую
   часть битых ссылок. Пункты 1.1 и 1.2 независимы, можно параллельно.
3. 1.3 восстановление 10 утраченных картинок (материал — архив site-backup-html).
4. 1.4 ремонт разметки портфолио и трёх адресов на странице «Изготовление...» —
   после 1.3.
5. 2.1 исключение 404-адреса из sitemap.xml — независимо, в любой момент.
6. 3.1 мессенджеры — ручная проверка.
7. 2.2 keywords — стратегическое решение, к срокам не привязано.
