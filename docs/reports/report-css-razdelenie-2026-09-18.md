## Шаг 3. Скриншотный протокол

Полностраничный снимок через full_page у Chromium оставляет секции UIkit
scrollspy прозрачными. Принят детерминированный протокол: вьюпорт
растягивается на всю высоту document.body.scrollHeight (потолок 16 000 px),
снимок обычный. База «до» переснята в том же протоколе (skriny-do,
skriny-chistka — по 20 снимков).

## Шаг 4. Разделение на слои

### Вынос inline-стиля
На каждой странице был inline <style> ~46 КБ (настроечный стиль темы),
одинаковый на всех страницах, кроме одного правила .antidrone-hero
(отличались только формы путей). Вынесен в inc/css/theme-inline.css с
корневыми абсолютными путями; из html удалён. Экономия: 46 КБ × 458 страниц
→ один кешируемый файл.

### Классификация правил
5 412 правил custom+theme-child распределены по использованию классов:
- common: 5 362 (классы общие для типов или динамические — префиксы
  uk-, shop-, cf-, fa- и т. п.);
- page-kartochka-tovara: 19, page-info-stranica: 26, page-korzina: 5.
Слои page-* получились крошечными: словарь классов карточек — это в основном
переименованные движковые классы (shop-*), часть которых JS добавляет
динамически, поэтому они отнесены к общему слою (консервативно, чтобы не
потерять стили корзины на других страницах).

### Critical первого экрана
Собран Playwright-ом на представителях каждого типа (2 вьюпорта: 1366×900,
375×812): правило попадает в critical, если у него есть элемент в первом
экране; плюс все правила без классов (html, body, :root) и @font-face;
@keyframes не инлайнится. Инлайнится в <head> перед </head>; правила
дублируются в слоях (стандартная практика).

страница корректна в любом состоянии.
