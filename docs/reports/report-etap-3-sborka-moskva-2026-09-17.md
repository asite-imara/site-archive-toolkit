## Что сделано

Этап 3 закрывает функциональную часть сборки: добавление в корзину, страница
корзины с оформлением заказа, поиск по каталогу, фильтры разделов, обновляемые
цены. Всё клиентское — на чистом JS без библиотек, серверное — один PHP-файл.

## 1. Состав разделов каталога (точное восстановление)

В архиве каждый раздел показывает только первые 24 карточки, полный состав
неизвестен. Решение: состав снят с живого сайта через AJAX каталог-фильтра
(`?cf_ajax=1&cf_offset=0,24,...`, заголовок X-Requested-With) — скрипт
TMP/33_live_sostav.py, результат inventory/etap-3/sostav-live.json.

- 33 из 34 разделов — состав и порядок с живого сайта;
- 1 раздел — из архива (дописывание по совместимости параметров), отклонение
  от «из N» — 1 карточка (73 против 72), задокументировано;
- контрольная сверка по архиву: расхождений 0 из 34; порядок карточек сборки
  совпадает с живым сайтом — начальный вид раздела без фильтров корректен.

## 3. Клиентские скрипты (TMP/stage3/ → site/inc/js/)

- **prices.js** — загружает prices.json, подставляет актуальные цены в
  разметку (data-price-id) и в блоки добавления в корзину. Цены правятся
  правкой одного JSON без пересборки.
- **cart.js** — корзина на localStorage (ключ oporaCartMsk):
  - добавление с любой карточки (блок data-cart-add, кнопка «В корзину»),
    отклик кнопки «Добавлено», счётчик в шапке;
  - страница korzina.html: таблица товаров, изменение количества, удаление,
    итоги (товары + доставка + всего);
  - оформление: проверка имени/телефона/почты/согласия, отправка JSON на
    /order.php, после успеха — корзина очищается, показывается номер заказа;
  - цели Метрики: lid_form_cart (добавление), lid_form_order (заказ);
    счётчик подключается на этапе 6.
- **filter.js** — клиентский фильтр разделов: чекбоксы опций, диапазон цен,
  сортировка (по умолчанию / цена / цена вниз), «Показать ещё» по 24,
  состояние фильтра в адресе страницы (ссылку можно передать), карточки
  рендерятся по шаблону из статичной разметки раздела.
- **search.js** — поиск на search.html по search-index.json (все слова
  в названии и подзаголовке), карточки как в разделах, «Показать ещё».

## 4. Обработчик заказа (site/order.php)

По образцу form-handler.php лендинга kirov:

- приём JSON (POST), проверка имени и телефона или почты, honeypot-поле;
- письмо на [почта цели moskva] через SMTP smtp.timeweb.ru:587 (STARTTLS),
  скрытая копия [адрес скрытой копии] (через RCPT TO, без заголовка Bcc);
- резервная отправка через mail() при недоступности SMTP;
- журнал заказов orders.csv (CP1251, разделитель «;», блокировка файла);
- ошибки почты — mail-errors.log;
- .htaccess закрывает orders.csv и mail-errors.log от веб-доступа.

1. Поведенческая проверка скриптов в браузере (добавление в корзину, фильтр,
   поиск, отправка заказа) не выполнялась — нет браузерной автоматизации.
   Рекомендуется проверить на этапе 7 перед деплоем (или на тестовом
   поддомене после размещения).
2. Форма заказа на korzina.html — поля как в архиве (самовывоз/наличчные
   по умолчанию). Если для Москвы нужны другие способы доставки/оплаты —
   правится разметка korzina.html без пересборки.
3. order.php при локальной проверке отдаётся http.server как текст —
   реальное исполнение PHP проверится только на хостинге.
