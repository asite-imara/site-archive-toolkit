# Отчёт: инвентаризация адресов сайта prom-opora.ru

Дата: 2026-09-16
Задача: полный актуальный перечень страниц сайта с мета-данными и типами; перечень битых ссылок с причинами. Этап методики скилла «Полная статическая копия сайта» (план docs/reports/plan-prom-opora-2026-09-15.md, раздел «Задача на проработку: инвентаризация адресов сайта»).

## Что сделано

1. Скачаны карты sitemap.xml основного домена и стейджинга; у kirov.prom-opora.ru карты нет (одностраничник). robots.txt снят и учтён (Clean-param: orderby, option_tu, cf_price_min/max, option_type_coverage, option_full_height; Disallow: /inc/, /*/page/, /*?s=, /service/).
2. Сверка main и new: пути идентичны (462 = 462), расхождений и дублей с параметрами нет — стейджинг зеркалит основной домен.
3. Обход 462 страниц из карты (скачивание HTML с паузой 0,4 с, повтор при 429/503): 461 ответ 200, одна 404. Редиректов нет. HTML сохранён в html/ (67 МБ) для повторных разборов без нагрузки на сервер.
4. Извлечены title, description, keywords, canonical, H1, тег base; собраны все ссылки (a, img, srcset, стили, скрипты, iframe) с указанием страниц-источников.
5. Проверка доступности 4 985 уникальных адресов (HEAD с переходом на GET при 405/403; паузы; повтор при 429/503): 4 872 — 200, 97 — 404, 14 — некорректный адрес, 2 — ошибка соединения.
6. Классификация типов страниц (шаблоны адресов + потомство в sitemap + ссылки на карточки + title), сборка двух CSV, markdown-сводки и настоящего отчёта.

## Отступление от плана (зафиксировано)

Вместо wget --spider по всему сайту (25 тыс. адресов, часы нагрузки с паузами) обход сделан обходчиком на Python stdlib по списку sitemap: скачивание 462 страниц даёт ту же полноту находки ссылок, а обнаруженные в разметке адреса сверяются с картой выборочно. Основание: раздел «Когда всё-таки Python» справки spravka-wget-zerkalirovanie-saytov-2026-09-16.md. Итог: 100 % контентных адресов в разметке входят в sitemap — полнота охвата подтверждена до скачивания, как и требовалось.

## Находки для SEO и разработки

1. 404 в карте сайта: /katalog/kronshtejn-1k1-0-5-0-5-f2-czink-xolodnyij/ присутствует в sitemap.xml, но удалён с сервера. Убрать из карты или восстановить адрес.
2. Тег base на стейджинг: на живых карточках /katalog/rmp-14/ и /katalog/zf-20-4-k300-1-5/ стоит base href="https://new.prom-opora.ru/" — все относительные ссылки и картинки этих страниц идут на поддомен стейджинга. Кроме того, 60 ссылок в разметке ведут на new.prom-opora.ru. Требует правки.
3. Keywords пусты на всех 462 страницах — заполненность нулевая (снимок для аудита).
4. Битые ссылки: 113. Основная масса — jpeg-картинки в /upload/ (404), сконцентрированы на странице «Изготовление металлоконструкций на заказ» и в карточках каталога; подтверждает известный дефект битых jpeg (список — в bitye-ssylki...csv). Иконки grid-product-card-icon-0X.jpeg (404) на 3 страницах.
5. Дефект разметки: на странице /izgotovlenie-metallokonstrukczij-na-zakaz/ три адреса картинок разорваны внутри атрибута («https://prom-opora.ru/ p-content/uploads/...»), на /portfolio/ десять src с припиской «width=» без значения — картинки не открываются.
6. Внешние: viber.click/7XXXXXXXXXX отдаёт 404; t.me и wa.me не проверились из-за ошибки соединения на стороне замера — проверить вручную.
7. Позитив: canonical на всех 462 указывает на себя; редиректов нет; внутренних контентных страниц вне sitemap не найдено (охват карты полный).

## Для скилла «Полная статическая копия сайта» (пополнение этапа «инвентаризация адресов»)

Порядок подтвержден как рабочий: robots.txt → sitemap (все карты) → сверка зеркал → обход HTML-страниц из карты с извлечением меты и ссылок → сверка охвата (ссылки против карты) ДО скачивания → проверка кодов всех уникальных адресов (HEAD, GET-фолбэк) → классификация по потомству в карте и ссылкам на карточки → два CSV. Устойчивые решения: ручное следование редиректам с записью цепочки; повтор при 429/503; сохранение HTML для повторных разборов; тег base учитывать при разборе ссылок; классификация глубины 3 по числу ссылок на карточки (потомков в карте может не быть).

## Что осталось / требует внимания

- Решения по находкам 1-2 (404 в карте, base на стейджинг) — на согласование; правок страниц не делал (граница).
- Ручная проверка t.me/wa.me; разметка портфолио и страницы «Изготовление...» — кандидаты на ремонт после одобрения.
- Валидация классификации человеком: 26 подразделов выделены автоматикой (ссылки на карточки), 4 посадочных — по списку; спорных «требует решения» не осталось, поэтому выборку стоит пролистать глазами в CSV.
- Скачанные html/ (67 МБ) можно удалить после приёмки — по границе не удалял без разрешения.
